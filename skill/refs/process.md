## 1. 리서치 페이즈 (Research Phase)

| 복잡도 | 리서치 요구사항 | 산출물 |
|--------|----------------|--------|
| 1-2pt | 선택사항 | 간단 메모 |
| 3-4pt | **필수** (기본 리서치) | 기술 선택 근거, 영향 범위 |
| 5pt+ | **필수** (심층 리서치) | 비교 분석표, PoC 결과, 리스크 평가 |

### 리서치 프로세스
1. **범위 정의**: 조사할 영역 명시
2. **자료 수집**: 코드베이스 분석, 패턴 검색, 의존성 확인
3. **분석**: 대안 비교, 장단점 평가
4. **결론**: 권장안 + 근거 문서화

## 2. 리서치 게이트 (Research Gate)

리서치 완료 판정 체크리스트 (5개 항목 모두 충족):

- [ ] **범위 완전성**: 식별된 모든 영역 조사 완료
- [ ] **대안 분석**: 최소 2개 이상 대안 비교
- [ ] **영향 범위**: affectedFiles 목록 도출 완료
- [ ] **리스크 식별**: 알려진 리스크 + 완화 방안 기술
- [ ] **근거 문서화**: 선택 이유가 데이터/코드 기반으로 기술됨

> 3pt 미만은 리서치 게이트 생략 가능

## 4. in_design 스테이지

설계 단계에서의 피드백 라운드:

| 복잡도 | 최소 피드백 라운드 | 승인 방식 |
|--------|-------------------|-----------|
| 1-2pt | 0 (설계 생략 가능) | auto_proceed |
| 3-4pt | 2라운드 | auto_proceed |
| 5-6pt | 3라운드 | user_approval |
| 7pt+ | 5라운드 | user_approval |

---

## 5. 피드백 카운터 시스템

### 라운드 규칙
- **2라운드 (3-4pt)**: Designer ↔ TPO 교차 검토
- **3라운드 (5-6pt)**: Designer ↔ TPO ↔ PM 삼자 검토
- **5라운드 (7pt+)**: 전체 팀 검토 + 사용자 중간 확인

### addressed 규칙
```
피드백 항목별 상태:
- addressed: 반영 완료 (근거 명시)
- deferred: 다음 이터레이션으로 연기 (사유 명시)
- rejected: 미반영 (사유 명시, 요청자 동의 필요)

모든 항목이 addressed/deferred/rejected 상태여야 라운드 완료
```

---

## 6. 승인 방식

### user_approval (5pt+)
```
1. 설계 문서 요약 제시
2. 주요 결정사항 나열
3. 사용자에게 명시적 승인 요청
4. "승인", "진행해" 등 확인 후 다음 단계
```

### auto_proceed (1-4pt)
```
1. 설계 문서 요약 제시 (정보 제공)
2. 5초 대기 후 자동 진행
3. 사용자가 "잠깐" / "수정" 시 중단
```

## 7. TPO 프로세스 리뷰 체크포인트

TPO는 4개 체크포인트에서 프로세스 준수를 검증:

| # | 시점 | 검증 내용 |
|---|------|-----------|
| 1 | **작업 시작 전** | 티켓 존재 확인, 위임 체인 정당성, 리서치 완료 여부 |
| 2 | **Gate 1 전** | 설계 문서 완성도, 피드백 라운드 충족, Impact Scope 분석 |
| 3 | **Gate 2 전** | 구현 완성도, 테스트 통과, Evidence-Based 검증 |
| 4 | **Gate 3 후** | QA 결과 확인, Match Rate, 최종 보고서 |

## 8. 반복 정제 (Iterative Refinement)

모든 산출물은 4단계 정제 프로세스를 거침:

```
Draft (60%) → Review (80%) → Edge (95%) → Polish (100%)
```

| 단계 | 완성도 | 초점 | 행동 |
|------|--------|------|------|
| **Draft** | 60% | 핵심 기능/구조 | 주요 로직 구현, 빠른 프로토타이핑 |
| **Review** | 80% | 피드백 반영 | 코드 리뷰, 설계 검증, 누락 보완 |
| **Edge** | 95% | 엣지 케이스 | 에러 처리, 경계값, 예외 상황 |
| **Polish** | 100% | 품질 마감 | 린트, 포맷, 문서화, 최종 테스트 |

### 단계별 진행 기준
- Draft → Review: 핵심 기능 동작 확인
- Review → Edge: 모든 피드백 addressed
- Edge → Polish: 테스트 커버리지 충족
- Polish → 완료: Gate 통과
