# 컨텍스트 관리 가이드

## 왜 컨텍스트 관리가 중요한가?

Claude Pro 모델은 200K 토큰 컨텍스트 윈도우를 가지지만, 스킬 규칙 + 코드 + 대화 내용이 쌓이면 빠르게 소진됩니다. Dream Team Pro는 이를 최소화하도록 설계되었습니다.

## 3-Layer Lazy Loading

```
Layer 0: SKILL.md 코어          ~4KB   [항상 로드]
Layer 1: 활성 역할 프롬프트      ~1.5KB [위임 시만]
Layer 2: 프로세스 참조 문서      ~2-3KB [필요 시만]
─────────────────────────────
총 오버헤드:                   ~4-8KB
```

### Layer 0: SKILL.md 코어 (항상 로드)
스킬 호출 시 자동 로드되는 핵심 규칙. 위임 경로, 복잡도 테이블, 게이트 요약 등 마스터가 매 턴 참조하는 최소 정보만 포함.

### Layer 1: 에이전트 프롬프트 (위임 시)
Task tool로 에이전트를 스폰할 때, 해당 역할의 `agents/{role}.md`만 로드. 다른 역할의 프롬프트는 로드하지 않음.

### Layer 2: 참조 문서 (필요 시)
`refs/` 디렉토리의 상세 문서는 실제로 필요한 시점에만 Read tool로 로드. 예: Gate 검증 시 `refs/quality-gates.md`, 위임 구조 확인 시 `refs/delegation.md`

## 컨텍스트 절약 팁

### 1. 복잡한 작업은 단계별로
한 번에 모든 것을 요청하지 말고, 단계별로 나누어 진행하면 컨텍스트를 효율적으로 사용합니다.

```
# 좋은 예
"로그인 기능의 기획을 먼저 해줘"
→ (기획 완료 후)
"이제 설계 진행해줘"

# 비효율적 예
"로그인, 회원가입, 비밀번호 찾기, 프로필 수정을 한번에 만들어줘"
```

### 2. /compact 활용
대화가 길어지면 Claude Code의 `/compact` 명령으로 컨텍스트를 압축.
Dream Team Pro의 핵심 규칙은 compact 후에도 유지되도록 설계.

### 3. 세션 분리
큰 프로젝트는 기능 단위로 세션을 분리:
- 세션 1: 로그인/인증 기능
- 세션 2: 대시보드 기능
- 세션 3: 결제 기능

### 4. 티켓으로 컨텍스트 전달
티켓(`.dream-team/tickets/`)이 세션 간 컨텍스트 전달 수단.
이전 세션의 결과를 티켓에 기록해두면 새 세션에서 연속 작업 가능.
