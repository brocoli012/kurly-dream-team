# Kurly Dream Team Pro

AI 에이전트 팀 협업 시스템 for [Claude Code](https://claude.ai/claude-code).

실제 개발팀처럼 **마스터 - PM - TPO - 디자이너 - 개발자 - QA** 역할별 AI 에이전트가 협업하여 소프트웨어를 개발합니다.

## 특징

- **역할 기반 위임**: 마스터가 Task tool로 전문 에이전트에게 작업 위임
- **복잡도 기반 프로세스**: 1-2점(단순) ~ 7점+(복잡)에 따라 자동으로 프로세스 조절
- **품질 게이트**: 6단계 품질 관문 (Research → Story → Prototype → Design → Dev → QA)
- **컨텍스트 최적화**: Claude Pro에서도 효율적으로 동작하도록 3-Layer Lazy Loading 설계
- **다양한 프로젝트 지원**: 웹서비스, 모바일앱, 웹게임, 스킬 개발

## 에이전트 구성

```
┌──────────────────────────────────────────────────────────┐
│                     🎯 마스터 (Opus)                      │
│         총괄 조율 · 요청 분석 · 위임 · 품질 검수            │
└────┬──────────┬──────────┬──────────┬──────────┬────────┘
     │          │          │          │          │
     ▼          ▼          ▼          ▼          ▼
  ┌──────┐  ┌──────┐  ┌───────┐  ┌──────┐  ┌──────┐
  │  PM  │  │디자이너│  │  TPO  │  │ 개발자 │  │  QA  │
  │      │  │      │  │(Opus) │  │      │  │      │
  │ 기획  │  │UI/UX │  │기술설계│  │ 구현  │  │ 검증  │
  └──────┘  └──────┘  └───────┘  └──────┘  └──────┘

  개발자 종류:
  ├── 풀스택 (dev-full)      ├── iOS (dev-ios)
  ├── 백엔드 (dev-back)      ├── Android (dev-android)
  ├── 프론트엔드 (dev-front)  ├── 게임 (dev-game)
  └── 프로토타입 (dev-proto)
```

| 에이전트 | 역할 | 모델 | 스폰 조건 |
|---------|------|:----:|----------|
| **마스터** | 총괄 조율, 품질 검수 | Opus | 항상 |
| **PM** | 기획, 요구사항, 인터뷰 | 동적 | 5점+ |
| **TPO** | 기술 설계, 과제 분해, 모델 라우팅 | Opus | 3점+ |
| **디자이너** | UI/UX 설계, 와이어프레임 | 동적 | 5점+ (UI 변경 시) |
| **개발자** | 코드 구현, 테스트 | 동적 | 항상 |
| **QA** | 테스트, Gap Detection, Match Rate | 동적 | 3점+ |

## 위임 경로

### 웹/앱 프로젝트

| 복잡도 | 경로 | 예시 |
|:------:|------|------|
| 1-2점 | Master → Developer | 버튼 색상 변경, 텍스트 수정 |
| 3-4점 | Master → TPO → Dev → QA | 검색 필터 추가, API 엔드포인트 수정 |
| 5점+ | Master → PM → Designer → TPO → Dev → QA | 회원 시스템, 결제 플로우 |

### 게임 프로젝트

| 복잡도 | 경로 | 예시 |
|:------:|------|------|
| 1-2점 | Master → dev-game | 버그 수정, 파라미터 조정 |
| 3-4점 | Master → TPO → dev-game → QA | 새 아이템 시스템 |
| 5점+ | Master → PM → Writer → dev-proto → Designer → TPO → dev-game → QA | 새 게임 스테이지 |

## 주요 개념 설명

### 복잡도 점수란?

마스터가 처음 요청을 받으면 작업의 규모를 추정합니다:

| 점수 | 난이도 | 기준 | 예시 |
|:----:|:-----:|------|------|
| 1-2 | 단순 | 단일 파일, 명확한 작업 | 텍스트 수정, 색상 변경 |
| 3-4 | 보통 | 여러 파일, 일반적 복잡도 | 필터 추가, API 수정 |
| 5-6 | 복잡 | 다중 시스템, 아키텍처 | 인증 시스템, 결제 플로우 |
| 7-10 | 매우 복잡 | 대규모, 보안, 성능 | 시스템 리뉴얼, 마이그레이션 |

### 티켓이란?

3점 이상의 작업에서 자동 생성되는 작업 추적 문서입니다.
`.dream-team/tickets/` 폴더에 저장되며, 에이전트 간 컨텍스트 전달 수단으로 사용됩니다.

```
TASK-001: 카테고리 필터 구현
├── 복잡도: 4
├── 상태: in_progress
├── 담당: dev-full
├── 요구사항: [...]
└── 산출물: [...]
```

### 승인 모드란?

5점+ 작업에서 마스터가 사용자에게 묻습니다:
- **"승인 후 개발"** — TPO가 설계를 완료하면 사용자에게 보여주고 승인을 받은 후 개발
- **"바로 개발"** — 설계 완료 후 자동으로 개발 진행

### Evidence-Based Completion이란?

개발자가 "다 했습니다"라고 말하는 것으로는 부족합니다.
반드시 **실행 결과를 증거로 첨부**해야 합니다:

```
✅ 좋은 예: "빌드 성공 (exit code 0), 테스트 15/15 통과"
❌ 나쁜 예: "아마 잘 될 겁니다", "테스트는 통과할 것 같습니다"
```

## 컨텍스트 최적화

기존 드림팀 스킬 대비 **컨텍스트 사용량 77% 절감**:

| | 기존 | Pro Edition |
|---|:---:|:---:|
| SKILL.md | 17KB | **7KB** |
| 초기 로드 | 17KB+ | **7KB** |
| 에이전트 참조 | 모든 역할 혼재 | **해당 역할만** |
| 최대 오버헤드 | ~47KB | **~11KB** |

### 3-Layer Lazy Loading

```
Layer 0: SKILL.md 코어 (항상 로드)        ~7KB   ← 핵심 규칙만
Layer 1: 활성 역할 프롬프트 (위임 시)      ~1.5KB ← 해당 역할만
Layer 2: 프로세스 참조 (필요 시)           ~3-5KB ← 해당 문서만
```

필요한 것만 필요한 때에 로드하여 Claude Pro의 컨텍스트 윈도우를 효율적으로 사용합니다.
